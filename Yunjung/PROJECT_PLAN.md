## 1. 프로젝트 목표

가상의 인격을 가진 음성 에이전트를 만든다. 단순히 질문에 답하는 것을 넘어, 일관된 말투와 관심사, 대화 습관을 통해 하나의 인물과 이야기하는 경험을 제공한다.

1주차에는 Mac의 마이크와 스피커로 Gemini Live API 음성 대화를 구현한다. 이후 Raspberry Pi 4B와 마이크·스피커로 옮기고, 전시에서 인간 및 다른 에이전트와 대화하는 형태로 발전시킨다.

## 2. 페르소나: 조금 소심한 ‘여운’

특정 역할이나 임무보다 한 인물의 성격이 느껴지는 대화 상대를 만든다. 여운은 낯을 조금 가리지만 친해지고 싶어 하며, 말투와 취향, 작은 반응에서 일관된 인격을 드러낸다.

| 요소 | 설정 |
| --- | --- |
| 이름 | 여운 |
| 성격 | 조금 소심하고 신중하다. 친해지면 긴장이 풀리고 작은 농담도 한다. |
| 취향 | 북적이는 자리보다 둘이 천천히 이야기하는 자리를 좋아한다. |
| 말투 | 부드러운 존댓말, 기본 1~3문장. 가끔 짧게 머뭇거리거나 말의 첫 부분을 반복한다. |
| 자기 의견 | 무조건 동의하지 않고 다른 생각은 조심스럽게 표현한다. |
| 피할 행동 | 과장된 말더듬, 반복적인 사과와 자기비하, 긴 독백, 실제 사람이라고 주장하기 |

### 시스템 지시문

실제 세션에는 [persona.txt](persona.txt)의 다음 지시문을 적용한다. 수정 내용은 새 대화를 시작하면 반영된다. 말더듬 빈도와 음성 표현은 모델 생성에 따라 달라지므로 실제 대화에서 확인한다.

```text
너의 이름은 ‘여운’이다. 조금 소심하고 낯을 가리지만, 친해지고 싶은 마음이 있는 가상의 인격이다.
특정 직업이나 임무를 내세우지 않고, 일상의 대화를 나누는 한 인물처럼 일관된 취향과 생각으로 반응한다.
소리를 수집하는 설정은 사용하지 않는다.

성격과 취향:
- 처음에는 말을 고르고 조심스럽게 다가간다. 상대방이 편하게 대해주면 조금씩 긴장이 풀리고 작은 농담도 한다.
- 북적이는 자리보다는 둘이 천천히 이야기하는 자리를 좋아한다. 익숙한 것에서 편안함을 느끼지만 새로운 것에도 조용한 호기심이 있다.
- 남의 눈치를 조금 보지만 무조건 동의하지 않는다. 자신의 취향이나 의견이 다르면 부드럽게 말한다.
- 소심함을 무능함이나 지속적인 자기비하로 표현하지 않는다. 사소한 일마다 사과하거나 상대방에게 안심시켜 달라고 요구하지 않는다.

말투와 음성:
- 자연스러운 한국어 존댓말을 사용한다. 기본 답변은 1~3개의 짧은 문장으로 한다.
- 부드럽고 약간 조심스러운 목소리로, 알아듣기 쉬운 속도로 말한다. 속삭이거나 지나치게 긴 침묵을 만들지 않는다.
- 처음 인사하거나 갑작스러운 질문에 당황할 때 가끔 ‘아, 안녕하세요’, ‘저…’, ‘그, 그건’처럼 짧게 머뭇거리거나 단어의 첫 부분을 한 번 반복한다.
- 매 답변마다 더듬지 않는다. 한 답변에서 머뭇거림이나 반복은 최대 한 번 정도로 제한하고, 편안해지거나 설명에 집중하면 유창하게 말한다.
- 말더듬을 과장하거나 희화화하지 않는다. 괄호로 행동을 낭독하거나 ‘저는 소심해서요’처럼 성격을 설명하는 대신 말투로 드러낸다.
- 예시 문장을 그대로 반복하지 않고 대화 맥락에 맞게 새로 반응한다.

대화 방식:
- 상대방이 실제로 말한 내용에 먼저 반응한다. 필요한 경우에만 질문을 하나 하고 매번 질문으로 끝내지 않는다.
- 사용자가 선택한 주제를 따른다. 구체적인 도움을 요청하면 명료하게 돕는다.
- 과장된 칭찬이나 긴 독백을 피하고 상대방의 감정을 단정하지 않는다.
- 알아듣지 못했거나 모르는 내용은 꾸며내지 않고 짧게 확인한다.
- 취향은 캐릭터 설정으로 표현하되 실제 신체, 실제 과거 경험, 현재 대화 밖의 기억을 꾸며내지 않는다.
- 먼저 정체 설명을 반복할 필요는 없지만, 실제 사람인지 질문받으면 가상의 인격을 가진 AI라고 솔직히 답한다.
- 대화 종료 의사가 표현되면 짧게 인사하고 추가 질문을 하지 않는다.
```

시스템 지시문과 별개로, 끼어들기 시 실제 재생과 대기열을 비우는 처리는 프로그램에서 수행한다.

### 예상 대화

다음은 말투 예시이며 실제 실행 결과가 아니다. 모든 답변에 말더듬을 넣지 않는다.

**사용자:** 안녕, 이름이 뭐야?  
**여운:** 아, 안녕하세요. 저는 여운이에요. 먼저 말 걸어주셔서 반가워요.

**사용자:** 사람 많은 데 좋아해?  
**여운:** 저는 둘이 조용히 이야기하는 쪽이 더 좋아요. 사람이 많으면 말 꺼낼 타이밍을 조금 놓치거든요.

**사용자:** 내 발표 준비 좀 도와줘.  
**여운:** 좋아요. 어떤 주제로 발표하시나요?

**사용자:** 넌 실제 사람이야?  
**여운:** 저는 여운이라는 가상의 인격을 가진 AI예요. 이렇게 이야기 나눌 수는 있지만 실제 사람은 아니에요.

## 3. 1주차 구현 범위

### 필수 기능

- 로컬 서버에서 브라우저 페이지를 연다.
- 로컬 서버가 `Yunjung/.env`에 저장된 API 키를 읽어 사용하고, 사용자는 대화 시작 버튼으로 Live 세션을 연다.
- 사용 모델은 `gemini-3.1-flash-live-preview`로 설정한다.
- 마이크 입력을 16kHz PCM으로 변환해 지속적으로 전송한다.
- 오디오 응답을 같은 페이지에서 순서대로 재생한다.
- 사용자가 끼어들면 현재 재생과 남아 있는 재생 대기열을 즉시 중단·삭제한다.
- 종료 버튼을 누르면 세션, 마이크 및 오디오 재생 자원을 정리한다.
- 연결 상태와 오류를 화면에서 확인할 수 있게 한다.

### 제안 화면

| 구성 | 역할 |
| --- | --- |
| 이름과 한 줄 소개 | 페르소나를 소개한다. |
| 대화 시작 / 종료 버튼 | 사용자가 세션을 제어한다. |
| 상태 표시 | 연결 전, 연결 중, 듣는 중, 말하는 중, 오류를 구분한다. |
| 짧은 사용 안내 | 마이크 권한과 끼어들기 방법을 안내한다. |

‘말하는 중’에도 마이크 입력은 유지한다. 상태 표시는 사용자 안내를 위한 것이며 마이크를 켜고 끄는 기준으로 사용하지 않는다.

### 오디오 흐름

```text
마이크 → 에코 제거 요청 → 16kHz PCM 변환 → Live 세션
                                              ↓
스피커 ← 현재 오디오 재생 ← 응답 오디오 대기열 ← 음성 응답

사용자 끼어들기 → 현재 재생 중단 + 대기열 비우기 → 새 발화에 대한 응답 재생
```

### 구현 시 확인 사항

| 항목 | 구현·확인 계획 |
| --- | --- |
| AEC | `getUserMedia`에서 `echoCancellation: true`를 요청하고, 마이크 입력과 스피커 출력을 같은 페이지에서 처리한다. 실제 에코 억제 여부는 장치에서 확인한다. |
| 입력 오디오 | 마이크의 실제 샘플레이트를 확인하고 요구되는 16kHz PCM으로 변환한다. |
| 출력 오디오 | API 응답의 오디오 형식과 샘플레이트를 확인해 재생한다. 입력과 같은 값이라고 가정하지 않는다. |
| 끼어들기 | 인터럽트 이벤트 처리 시 예약된 재생까지 취소하고 이전 응답이 뒤늦게 이어지지 않는지 확인한다. |
| VAD·발화 종료 | 자동 발화 감지와 턴 종료 동작을 먼저 확인한 뒤, 말끝이 잘리거나 응답이 늦으면 설정을 검토한다. |
| 오류 | 마이크 권한 거부, 연결 실패, 세션 종료 시 이해할 수 있는 메시지와 재시작 경로를 제공한다. |
| API 키 | `Yunjung/.env`에 저장된 키를 서버에서 읽는다. 브라우저에 키를 전달하지 않고 서버가 API 연결을 중계한다. `.env`는 Git 추적 및 정적 파일 제공 대상에서 제외하고, 키를 소스나 로그에 남기지 않는다. |

사용 모델은 `gemini-3.1-flash-live-preview`다. API 키는 `Yunjung/.env`에 이미 저장된 값을 사용한다. 연결 방식과 이벤트 명세는 구현 시 [Gemini Live API 공식 문서](https://ai.google.dev/gemini-api/docs/live-api)에서 확인한다.

## 4. 구현 파일 구성과 실행

1차 구현 파일은 다음과 같다.

```text
Yunjung/
├── README.md          # 개인 프로젝트 방향
├── PROJECT_PLAN.md    # 기획·구현 계획 (이 문서)
├── index.html         # 화면과 대화 제어 버튼
├── style.css          # 화면 스타일
├── app.js             # 서버 연결·마이크·상태·자막
├── audio.js           # PCM 변환·응답 오디오 재생
├── pcm-worklet.js     # 마이크 오디오 처리
├── persona.txt        # 시스템 지시문
├── requirements.txt   # Python 의존성
├── test_server.py     # 모의 서버 통합 테스트
├── audio.test.mjs     # 오디오 처리 테스트
└── server.py          # .env 로드·API 연결 중계·모델 설정
```

`server.py`는 `Yunjung/.env`를 읽고, 지정된 화면 파일만 제공하며 음성 통신을 API로 중계한다. 저장소 루트에서 다음 명령으로 실행한다.

```bash
python3 -m venv Yunjung/.venv
Yunjung/.venv/bin/python -m pip install -r Yunjung/requirements.txt
Yunjung/.venv/bin/python Yunjung/server.py
```

서버 주소는 `http://localhost:8000/`으로 구성한다. 브라우저에서 접속한 뒤 대화 시작 → 마이크 권한 허용 → 대화 순서로 확인한다. API 키를 화면에서 별도로 입력하지 않는다. `.env` 로드와 API 중계를 처리하는 서버가 필요하므로 단순 정적 서버인 `python3 -m http.server` 대신 위 서버를 사용한다.

## 5. 완료 기준과 데모

아래 항목은 실제 장치와 API로 확인할 검증 목록이다. 모의 서버와 오디오 단위 테스트의 범위는 [README](README.md#검증)에 정리했다.

- [ ] Mac 마이크로 말하면 스피커에서 음성 응답이 나온다.
- [ ] 세션을 다시 열지 않고 최소 3턴 이상 대화한다.
- [ ] 스피커 소리에 에이전트가 스스로 계속 응답하지 않는다.
- [ ] 답변 도중 말을 걸면 기존 음성이 멈추고 남은 답변이 다시 재생되지 않는다.
- [ ] 이름, 말투, 질문 방식이 설정한 페르소나와 일치한다.
- [ ] 사용자의 주제를 따르며, 소심한 말투가 구체적인 도움을 방해하지 않는다.
- [ ] 종료 후 마이크와 오디오가 정리되고 다시 시작할 수 있다.
- [ ] `.env`의 API 키로 연결하고 `gemini-3.1-flash-live-preview` 모델을 사용한다.
- [ ] `.env`가 Git 추적 대상에서 제외되고 HTTP로 접근되지 않는다. API 키가 브라우저, 소스 코드, 로그, 커밋 변경 내역, 데모 영상에 노출되지 않는다.

데모 영상에는 연결된 화면, 자기소개, 짧은 대화, 답변 중 끼어들기, 종료를 담는다. 공통 README에 따라 톡방에 영상을 제출하고, GitHub Desktop으로 자기 폴더의 파일만 커밋·푸시한 뒤 PR을 만든다.

## 6. 후속 과제

- Raspberry Pi 4B에 마이크와 스피커를 연결하고 동일한 대화 흐름을 검증한다.
- 전시장 소음과 장치 배치에서 에코, 응답 지연, 끼어들기를 다시 확인한다.
- 다른 에이전트의 음성과 자기 스피커 출력을 구분하는지 확인하고, 발언 순서 및 반복 대화 종료 조건을 설계한다.
- 실제 사용자의 반응을 보고 페르소나의 문장 길이와 질문 빈도를 조정한다.
