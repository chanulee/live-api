# minseo · Gemini Live Voice Agent

인터랙션디자인융합 2 · 1주차 과제.
맥 브라우저에서 마이크로 말하면 Gemini가 음성으로 답하고, 말을 끊으면 즉시 멈추는 최소 음성 에이전트.

## 실행

`minseo/🔴 서버 켜기.command` 를 **더블클릭**한다. 터미널이 열리면서 서버가 켜지고
1초 뒤 브라우저가 자동으로 열린다. 끄려면 그 터미널 창에서 `Control + C` 를 누르거나 창을 닫는다.

- 스크립트는 자기 위치를 기준으로 한 칸 위(저장소 루트)에서 서버를 띄운다. 폴더를 옮겨도 동작한다.
- 이미 8000 번 포트가 쓰이고 있으면 서버를 또 띄우지 않고 브라우저만 연다.
- 더블클릭이 안 되고 텍스트 편집기가 열리면 실행 권한이 없는 것이다. `chmod +x "minseo/🔴 서버 켜기.command"`.

터미널에서 직접 하려면 저장소 루트에서:

```bash
python3 -m http.server 8000
```

어느 쪽이든 `http://localhost:8000/minseo/` 를 연다.
`index.html` 을 더블클릭해서 `file://` 로 열면 마이크와 AudioWorklet 이 동작하지 않는다.
로컬 서버가 필요한 이유가 이것이다.

키는 [Google AI Studio](https://aistudio.google.com/api-keys) 에서 발급받는다.
넣는 방법이 두 가지이고 **둘 다 소스 파일을 건드리지 않는다.**

**1. 화면에서 넣기 (권장)** — 페이지 맨 위 `API KEY` 칸에 붙여넣고 저장을 누른다.
이 브라우저의 localStorage 에만 들어가므로 어떤 파일에도 기록되지 않는다.
따라서 커밋될 수 없다. 지울 때는 지우기를 누른다.

**2. `key.js` 에 넣기** — 다른 기기에서 매번 입력하기 싫을 때 쓴다.

```bash
cp key.example.js key.js
# key.js 를 열어 window.GEMINI_KEY 에 키를 넣는다
```

`key.js` 는 `.gitignore` 에 있어서 커밋 자체가 되지 않는다.

둘 다 있으면 화면에서 저장한 값이 이긴다. 화면 상단에 지금 어느 쪽을 쓰는지 표시된다.
표시에는 키의 글자가 나오지 않고 길이만 나온다. 데모 영상을 찍어도 키가 남지 않게 하려는 것이다.

**`app.js` 를 포함한 어떤 소스 파일에도 키를 쓰지 않는다.** 커밋 전에 지우는 걸 기억하는 방법은
2026-09-09 에 한 번 실패했다.

| 파일 | 역할 |
| --- | --- |
| `index.html` | Connect 버튼, 목소리 셀렉터, 레벨 미터, 파라미터 패널, 전사, 로그 |
| `app.js` | Live API 세션, 마이크 전송, 재생 큐, 끼어들기 처리 |

| `🔴 서버 켜기.command` | 더블클릭하면 로컬 서버를 켜고 브라우저를 연다 |

## 동작 흐름

README의 6단계를 그대로 따른다.

1. `python3 -m http.server` 로 띄운 로컬 페이지를 연다.
2. `wss://generativelanguage.googleapis.com/ws/...BidiGenerateContent` 로 세션을 열고
   `setup` 에 `responseModalities: ["AUDIO"]` 를 넣어 오디오로 답하게 한다.
3. 마이크를 16kHz PCM 으로 계속 `realtimeInput.audio` 에 실어 보낸다. 마이크는 끄지 않는다.
4. 돌아온 `serverContent.modelTurn.parts[].inlineData` (24kHz PCM) 를 같은 페이지의 스피커로 재생한다.
5. 끼어들면 예약된 `AudioBufferSourceNode` 를 전부 `stop()` 하고 큐를 비운다.
6. 3-5를 반복한다.

### 에코 (AEC)

`getUserMedia` 에서 `echoCancellation` / `noiseSuppression` / `autoGainControl` 을 켜서
브라우저 내장 AEC에 맡긴다. 마이크 입력과 스피커 재생이 **같은 페이지**에서 일어나야 작동하므로
재생도 이 페이지의 Web Audio로 한다.

### 버퍼 플러시 (끼어들기)

Gemini는 음성을 작은 조각으로 계속 보내기 때문에, 끊긴 뒤에도 잔여 조각이 도착한다.
두 겹으로 처리한다.

- **로컬 감지** — 재생 중에 마이크 RMS가 `INTERRUPT_RMS`(0.30)를 연속 5프레임(약 320ms) 넘으면
  즉시 큐를 비운다. 서버 신호보다 빨라서 체감상 바로 멈춘다.
- **서버 신호** — `serverContent.interrupted` 가 정본이다. 이게 오면 큐를 비우고 억제를 푼다.

로컬로 먼저 끊은 뒤에는 뒤늦게 도착하는 조각을 버리는 억제 구간에 들어간다.
`interrupted` 또는 `turnComplete` 가 오면 풀리고, 둘 다 안 와도 3초 뒤 자동으로 풀려서
영구히 벙어리가 되는 일은 없다.

## 개성

README의 "각자 개성을 조금씩 가진 음성 에이전트"에 대한 이번 주 답.

**자주 소리지르면서 얼척없게 말하는 4차원 에이전트.** 관심사는 말꼬리 물고 늘어지기 하나뿐이라,
상대가 한 말의 전체 뜻은 무시하고 방금 나온 단어 하나에 꽂혀서 그것만 파고든다.
첫인사는 콜드리딩이다 — 상대가 켜기 직전에 망설였다는 걸 아는 척하고, 이유는 안 알려준다.

개성을 프롬프트에만 두지 않았다. **끼어들기 임계값도 성격의 일부로 썼다.**
`INTERRUPT_RMS` 를 0.045에서 0.30으로 크게 올려서, 웬만큼 큰 소리로 말하지 않으면
하던 말을 끝까지 하고 만다. 소심하게 물러서지 않는 뻔뻔함이 수치로 들어가 있다.
VAD·barge-in 이라는 기술 요소를 그대로 캐릭터로 번역한 부분이다.

목소리는 화면 상단 셀렉터에서 6종을 바꿔가며 들어볼 수 있다. Live API는 목소리를
세션 `setup` 에서 정하기 때문에, `이 목소리 듣기` 는 세션을 다시 열어 같은 대사를 말하게 한다.

## 연결과 세션은 다른 것이다

화면에 상태가 둘 있다.

- **연결** — WebSocket 이 열려 있는가. 인터넷 연결과 같은 층이다.
- **세션** — 서버가 `setupComplete` 를 보내 대화가 실제로 시작됐는가. 경과 시간이 같이 뜬다.

`Connect` 는 연결을 여는 버튼이고, 세션은 그 뒤에 따라온다. 둘을 나눠 표시하는 이유는
문제가 났을 때 어디서 났는지가 바로 보이기 때문이다. 연결은 됐는데 세션이 안 열리면
`setup` 이 거부된 것이고, 연결부터 안 되면 키나 네트워크 문제다.

`세션 새로고침` 은 현재 세션을 버리고 새로 연다. SESSION 파라미터를 반영하는 유일한 방법이다.

### 세션 캐시 정리

세션이 끝날 때 이 세션에 속한 상태를 남김없이 지우고, 무엇을 지웠는지 로그에 남긴다.
재생 큐, 억제 타이머, 전사 버퍼, 끼어들기 카운터가 대상이다.
다음 세션이 이전 세션의 찌꺼기를 물려받지 않게 하려는 것이다.

서버 쪽 세션은 **재개하지 않는다.** Live API 의 세션 재개는 `setup` 에 `sessionResumption` 을
넣어야만 켜지는 opt-in 기능이고, 켜면 서버가 재개 토큰을 발급해 **종료 후 2시간** 동안
이전 세션을 이어받을 수 있다. 우리는 그 필드를 넣지 않으므로 매 연결이 완전히 새 세션이다.
화면의 `세션 재개 · 사용 안 함` 행이 그것을 표시한다.

## 두 가지 모드

화면 맨 위에 `손쉬운 모드` 와 `개발자 모드` 토글이 있다. **같은 값을 두 언어로 보여준다.**
값 자체는 하나이고 어느 쪽에서 바꾸든 같은 곳에 들어간다.

| | 손쉬운 모드 | 개발자 모드 |
| --- | --- | --- |
| 이름 | `얼마나 크게 말해야 끼어들 수 있나` | `끼어들기 임계` |
| 값 | `잘 안 끊김` + 작게 `0.300 RMS` | `0.300 RMS` |
| 반영 시점 | `지금 바로` / `다시 연결` | `LIVE` / `SESSION` |
| 묶음 | `에이전트` / `말을 언제 시작하고 끝내는가` / `끼어들기` | `세션 설정` / `API VAD` / `로컬 비공식` / `고정` |
| 설명 | 각 줄마다 무슨 일이 일어나는지 한 줄 | 없음 |
| 숨김 | 전송 단위 같은 내부 값 | 전부 표시 |

손쉬운 모드에서도 **원래 숫자를 지우지 않는다.** 느낌 단어 옆에 작게 같이 둔다.
느낌 단어만 남기면 "보통"이 정확히 몇인지 알 수 없어져서, 데모에서 값을 말할 수 없게 된다.

고른 모드는 localStorage 에 남아서 새로고침해도 유지된다.

## 파라미터 패널

`PARAMETERS` 패널은 이 프로그램이 실제로 쓰는 값을 보여주고, 그 자리에서 바꿀 수도 있다.
데모에서 "무엇을 어떤 값으로 돌리는지"를 말로 설명하지 않아도 되게 하려는 것이다.

패널은 네 그룹으로 나뉜다. **무엇이 API 규격이고 무엇이 우리가 만든 것인지 구분하는 것**이
이 구획의 목적이다. 섞어두면 직접 만든 값이 규격인 것처럼 보인다.

### API VAD · `setup.realtimeInputConfig`

문서에 있는 서버측 음성 감지 손잡이다. 서버 VAD 는 기본으로 켜져 있고,
`VAD 직접 지정` 을 켜야 아래 값들이 `setup` 에 실린다. 끄면 아무것도 안 보내고 서버 기본값이 쓰인다.

| 필드 | 하는 일 |
| --- | --- |
| `startOfSpeechSensitivity` | 말 시작을 얼마나 쉽게 인정할지. `HIGH` / `LOW` 두 단계 |
| `prefixPaddingMs` | 말 시작으로 확정하기 전 필요한 발화 지속 시간 |
| `endOfSpeechSensitivity` | 말 끝을 얼마나 쉽게 인정할지. `HIGH` / `LOW` |
| `silenceDurationMs` | 얼마나 조용해야 발화가 끝난 것으로 볼지. **endpointing 이 이것이다** |

켰을 때 쓰는 시작값(HIGH / 300 ms / HIGH / 800 ms)은 **우리가 고른 출발점이지
문서가 명시한 기본값이 아니다.** 문서는 기본값을 밝히지 않는다.

### 로컬 · 비공식

`끼어들기 임계`, `끼어들기 지속`, `억제 최대` 세 개는 **문서에 없다. 이 앱이 자체로 만든 층이다.**
서버의 `interrupted` 신호보다 먼저 재생을 끊으려고 브라우저 마이크 RMS 로 직접 판정한다.

**이 값들은 서버 VAD 를 바꾸지 않는다.** 슬라이더를 움직여도 서버가 언제 끼어들기를
인정하는지는 그대로다. 바뀌는 것은 우리 재생 큐가 얼마나 빨리 비워지는가뿐이다.
서버 VAD 를 조절하려면 위의 API 그룹을 써야 한다.

`끼어들기 임계` 는 `startOfSpeechSensitivity` 와, `끼어들기 지속` 은 `prefixPaddingMs` 와
개념이 겹친다. 즉 우리는 API 가 이미 주는 손잡이를 모르고 비슷한 것을 다시 만들었다.
그래도 지우지 않은 이유는 서버 왕복보다 빠르기 때문이다. 다만 **제어 수단이 아니라
지연 최적화**라는 것이 정확한 위치다.

### 반영 시점

각 행에 반영 시점이 붙어 있다.

| 표시 | 뜻 | 해당 파라미터 |
| --- | --- | --- |
| `LIVE` | 매 오디오 프레임마다 읽으므로 세션 중에 바꿔도 즉시 먹는다 | 끼어들기 임계·지속, 억제 최대 |
| `SESSION` | `setup` 이나 오디오 그래프를 만들 때 한 번만 쓴다. 세션을 다시 열어야 반영된다 | 모델, 목소리, 전사, 먼저 인사, 전송 단위, 시스템 지시 |
| `FIXED` | 규격이라 못 바꾼다 | 입출력 샘플레이트, 응답 형식, AEC, 세션 재개 |

SESSION 파라미터를 세션 도중에 바꾸면 경고가 뜨고 `세션 새로고침` 버튼이 강조된다.
바꾼 값이 반영된 줄 알고 데모하는 사고를 막으려는 것이다.

바꾼 값은 localStorage 에 저장되어 새로고침해도 남는다. `기본값으로` 를 누르면 되돌아간다.

값과 눈금은 `PARAM_DEFS` 정의를 런타임에 읽어 그린다. 화면에 숫자를 따로 적어두지 않았으므로
정의를 고치면 패널이 자동으로 따라오고, 표시와 실제가 갈라질 수 없다.
파생값(64 ms, 320 ms 같은 것)도 계산해서 표시한다.

같은 이유로 프레임 크기는 `params.frame` 하나가 단일 출처다.
`pcm-recorder.js` 는 이 값을 `processorOptions` 로 전달받는다. 두 곳에 적어두면 갈라지기 때문이다.

## 기본값

전부 화면에서 바꿀 수 있다. 코드에서 기본값을 바꾸려면 `app.js` 의 `PARAM_DEFS` 를 고친다.

| 파라미터 | 기본값 | 설명 |
| --- | --- | --- |
| 모델 | `gemini-3.8-live` | 수업 지정 모델 (09-16 master 기준으로 3.1 → 3.8) |
| 목소리 | `Fenrir` | Aoede / Puck / Charon / Kore / Zephyr |
| 전사 | `on` | setup 이 거부되면 off 로 두고 다시 연결 |
| 먼저 인사 | `on` | 세션이 열리면 콜드리딩 인사를 시킴 |
| 전송 단위 | `1024` | 64 ms. 작을수록 지연이 줄고 메시지가 늘어난다 |
| 끼어들기 임계 | `0.30` | 미터의 노란 선. 높을수록 안 물러선다 |
| 끼어들기 지속 | `5` | 320 ms. 잡음 오탐을 막는 최소 지속 |
| 억제 최대 | `3.0 s` | 로컬 판정 후 잔여 조각을 버리는 최대 시간 |

## 문제가 생기면

로그 창을 먼저 본다. WebSocket이 닫힌 코드가 찍힌다.

- **`code 1007`** — 모델 이름이나 `setup` 필드를 서버가 거부. `ENABLE_TRANSCRIPTION` 을 `false` 로
  바꿔보거나 `MODEL` 을 확인한다.
- **`code 1008`** / auth 관련 reason — API 키 문제.
- **AudioWorklet 로드 실패** — `file://` 로 열었을 가능성. `http.server` 로 다시 연다.
- **에코가 돈다 (Gemini가 자기 소리에 반응)** — 헤드폰을 쓰거나 `INTERRUPT_RMS` 를 올린다.
- **너무 쉽게 끊긴다** — `INTERRUPT_RMS` 를 올리거나 `INTERRUPT_FRAMES` 를 늘린다.
